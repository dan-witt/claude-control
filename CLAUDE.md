# claude-control

Session daemon, MCP server and tmux TUI for Claude Code sessions. Design and decisions: `DESIGN.md`.

## Tickets

Tracked in Linear, team Echowire (key `ECH`). v1 is [ECH-17](https://linear.app/echowire/issue/ECH-17). Reference the ticket key in branch names and commits.

## Development

- Checks: `uv run pytest`, `uv run ruff check . && uv run ruff format --check .`, `uv run pyright`.
- The installed tool is editable (`uv tool install --editable .`); the service runs this tree. After a code change: `systemctl --user restart claude-control`. After a dependency change: `uv tool install --editable . --force` first, or the service crash-loops on the import.
- The `mcp` SDK is 2.x (`MCPServer`, not v1's `FastMCP`); read its installed source rather than v1 examples.
- `claude-control events [-n N] [-s SESSION] [--raw]` prints captured hook events; `claude-control sessions [-a] [--json]` prints the daemon's session state.
- State-machine fixtures are scrubbed event sequences in `tests/fixtures/`, made with `scripts/fixture.py DB OUT --session ID [--from N --to N]` from a dev-daemon or live `events.db`. The script drops prompts, messages, tool input/output and paths, so fixtures can come from sessions doing real work; check new fixtures for leftovers anyway. Pick sequences deliberately: until 2026-10-23 harness sessions also posted to the live log.
- To test against a real session without touching the live daemon: run `serve` with `XDG_CONFIG_HOME`/`XDG_STATE_HOME` pointed at a scratch dir whose `config.toml` sets another `port`, and start `claude --setting-sources project,local --settings <file>` in a separate tmux server (`tmux -L <name>`), with the file generated by `hooks_install.apply({}, url)`. `--setting-sources` leaves out `~/.claude/settings.json`, which holds the live hooks; without it the test session posts to both daemons. For discovery, generate the file with `hook_entry(event, url)` for every documented event instead, so unhooked events show up. To test `launch_session` end to end, set `tmux_socket` and `launch_args = ["--setting-sources", "project,local", "--settings", "<file>", "--model", "haiku"]` in the scratch `config.toml`; launched sessions then go to the isolated tmux server and post to the scratch daemon. Pass the prompt as the last positional argument; typed prompts sometimes do not submit.

## Constraints that are easy to break

- The daemon must never start the tmux server in its own cgroup; see "tmux" in `DESIGN.md`.
- Use `claude agents --json` for session discovery; do not read `~/.claude/sessions/*.json` (undocumented).
- MCP tool names and state names are a contract consumed by other components; change them in `DESIGN.md` first.
- Nothing may write to the terminal while the TUI runs: it draws over the app. `claude-control tui` sends logging to `$XDG_STATE_HOME/claude-control/tui.log` (httpx2 logs every request at INFO).
